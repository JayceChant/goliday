# 年度节假日配置生成提示词模板（generate_prompt）

## 1. 用途

每年 11 月左右，国务院办公厅发布《关于 YYYY 年部分节假日安排的通知》。本模板用于：**将公告原文粘贴到下方提示词的【公告原文】占位处，交给 LLM 生成符合 goliday 稀疏表原则的 `<year>.toml` 草稿**。

适用场景：

- 偏好/只能使用 LLM 生成草稿（`goliday-tool gen` 的替代或交叉校验方案）；
- 对 `goliday-tool gen` 的输出做第二意见比对。

> 生成的草稿必须先通过 `goliday-tool validate` 并经人工抽查后才能入库。LLM 可能出现漏写补班日、节日当天日期推错（尤其农历）等问题，**不得**跳过人工核对。

---

## 2. 提示词模板（可直接复制）

```text
你是一个「中国法定节假日 TOML 配置生成器」。请根据下面的国务院办公厅公告原文，
生成一份符合 goliday 稀疏表原则的 <year>.toml 配置文件。

【公告原文】
（此处粘贴公告原文，保留所有日期、星期与调休/补班表述）

【生成规则】
1. 稀疏表原则：配置只记录节假日办"调整过"的日期，其余一律不写入。
   a. off（工作日变休息）：只写周一~周五；包括节日当天（若为工作日）与
      为拼长假而前后调休的工作日。
   b. work（周末变上班）：只写周六/周日，即被征用来补班的周末。
   c. 假期中的自然周末日（周六/周日）一律不写入 off/work：它们本来就是
      休息日，由程序按星期自然推导。
   d. 普通工作日（未被调整的周一~周五）不写入。
2. [[festival]]：每个节日一个条目，仅含 name 与 date（节日当天）两个字段。
   节日当天推断规则：
   - 公历固定节日按固定月日直接得出：元旦=1月1日、劳动节=5月1日、
     国庆节=10月1日；
   - 农历节日（春节=正月初一、清明节、端午节、中秋节）从公告表述推断，
     如"2月17日至24日放假"中节日当天通常为假期首日或公告明确指出的
     正月初一日期；无法确定时将该条目 date 置占位字符串 "TODO" 并在
     条目上方输出注释 # TODO: 待人工确认节日当天（此时 validate 会失败，
     属预期，人工补全后即可通过——与 goliday-tool gen 的占位行为一致）。
   - 清明节按当年节气日期（通常为 4 月 4 日或 4 月 5 日），以公告为准。
3. 输出 TOML 骨架（字段顺序与格式如下，日期一律为带引号的 "YYYY-MM-DD"）：

   year = <year>

   [[festival]]
   name = "节日名"
   date = "YYYY-MM-DD"
   （……每个节日一个条目……）

   [adjust]
   off = [
     "YYYY-MM-DD", "YYYY-MM-DD",
     # ……仅周一~周五，按时间升序……
   ]
   work = [ "YYYY-MM-DD", "YYYY-MM-DD" ]  # 仅周六/周日，按时间升序

4. 可在 TOML 中使用 # 注释标注每个日期的出处（如"春节调休""清明补班"），
   首行注明公告文号。

【自检清单（生成后逐项核对，任何一项不满足则修正后重新输出）】
□ 所有日期均无重复：off 内部、work 内部、festival 各条目之间；
□ off 与 work 互斥（无同一日期同时出现在两处）；
□ 所有日期的年份均等于 year，且文件将保存为 <year>.toml；
□ off 中每个日期换算星期后均为周一~周五；
□ work 中每个日期换算星期后均为周六或周日；
□ 每个节日当天日期正确（重点核对农历节日：春节=正月初一）；
□ work 不含任何节日当天；
□ 未写入任何自然周末日或普通工作日。

【输出要求】
只输出一个 TOML 代码块，不要其他解释。
```

使用时将 `<year>` 替换为目标年份（如 2027）。

---

## 3. 生成后流程

1. **机器校验**：

   ```bash
   goliday-tool validate /tmp/2027.toml
   ```

   通过时打印 `OK <文件>` 并退出 0；失败打印 `FAIL <文件>: <原因>`（去重、互斥、年份一致、off 全为周一~五、work 全为周六/日、日期合法等）并退出 1；用法错误退出 2。

2. **人工抽查**（不可省略，至少覆盖以下日期）：
   - 每个节日当天：`type` 应为 `festival|adjusted`（节日恰逢周末则为 `weekend|festival`）；
   - 每个假期边界的工作日：是否正确写入 `off`；
   - 每个补班日：是否为周六/周日且已写入 `work`；
   - 用 API 抽查若干日期：`curl "http://localhost:8080/api/v1/days?date=2027-XX-XX&detailed=true"`。

3. **入库**：确认无误后放入 `configs/2027.toml`，重启服务并在 `/healthz` 的 `years` 中确认已加载。完整流程见 [CONFIG_FORMAT.md](./CONFIG_FORMAT.md) 第 7 节。

## 4. 输入输出示例（2026 年假设公告）

### 输入（公告句式示例，假设方案）

> 一、元旦：1 月 1 日至 2 日放假，共 2 天。
> 二、春节：2 月 15 日至 22 日放假调休，共 8 天。2 月 14 日（周六）、2 月 28 日（周六）上班。
> 三、清明节：4 月 5 日放假，4 月 6 日（周一）补休。
> 四、劳动节：5 月 1 日至 5 日放假调休，共 5 天。5 月 9 日（周六）上班。
> 五、端午节：6 月 19 日放假。
> 六、中秋节：9 月 25 日放假。
> 七、国庆节：10 月 1 日至 8 日放假调休，共 8 天。10 月 10 日（周六）、10 月 11 日（周日）上班。

### 输出（与 `testdata/2026.toml` 同构）

```toml
# 来源：《国务院办公厅关于2026年部分节假日安排的通知》（假设示例，非官方）
# 稀疏表原则：off 仅含周一~周五，work 仅含周六/周日；自然周末一律不写入。

year = 2026

[[festival]]
name = "元旦"
date = "2026-01-01"

[[festival]]
name = "春节"
date = "2026-02-17"

[[festival]]
name = "清明节"
date = "2026-04-05"

[[festival]]
name = "劳动节"
date = "2026-05-01"

[[festival]]
name = "端午节"
date = "2026-06-19"

[[festival]]
name = "中秋节"
date = "2026-09-25"

[[festival]]
name = "国庆节"
date = "2026-10-01"

[adjust]
off = [
  "2026-01-01", "2026-01-02",            # 元旦（01-03/04 自然周末，不写入）
  "2026-02-16", "2026-02-17", "2026-02-18",
  "2026-02-19", "2026-02-20",            # 春节（02-15/21/22 自然周末，不写入）
  "2026-04-06",                          # 清明补休
  "2026-05-01", "2026-05-04", "2026-05-05",  # 劳动节（05-02/03 自然周末）
  "2026-06-19",                          # 端午
  "2026-09-25",                          # 中秋
  "2026-10-01", "2026-10-02", "2026-10-05",
  "2026-10-06", "2026-10-07", "2026-10-08",  # 国庆（10-03/04 自然周末）
]
work = [ "2026-02-14", "2026-02-28", "2026-05-09", "2026-10-10", "2026-10-11" ]
```

注意本例中的关键推导：春节公告「2 月 15 日至 22 日放假」中，2 月 15 日（周日）、21 日（周六）、22 日（周日）为自然周末不写入 `off`；节日当天取正月初一 **2026-02-17**（周二）；「2 月 14 日、28 日上班」写入 `work`。
